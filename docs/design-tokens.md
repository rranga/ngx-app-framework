# Phase 02 — Design-Token Foundation

## 1. Overview

Phase 02 introduces the initial CSS design-token foundation for **`ngx-app-framework`**.

Design tokens provide shared values for colors, spacing, typography, borders, elevation, and layering. Components consume these values through CSS custom properties instead of defining unrelated styling values independently.

The token foundation is implemented as a dedicated Angular-packaged library named:

```text
@rranga/ngx-design-tokens
```

The library is intended to provide reusable design styles to the Host application, the future native UI component library, Storybook documentation, and other consuming applications.

> The package name is configured locally. This does not mean the package has been published to npm.

## 2. Objectives

- Establish a consistent set of CSS custom properties.
- Provide light-theme defaults.
- Provide dark-theme overrides.
- Establish shared baseline styles.
- Demonstrate token consumption in the Host application.
- Verify that the styles are included in the application build.
- Prepare for future design-system documentation and component development.

## 4. Token Categories

### 4.1 Colors

The light theme defines custom properties for:

| Category                | Examples                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------- |
| Brand                   | `--ngx-color-primary`, `--ngx-color-primary-hover`, `--ngx-color-secondary`           |
| Semantic status         | `--ngx-color-success`, `--ngx-color-warning`, `--ngx-color-error`, `--ngx-color-info` |
| Background and surfaces | `--ngx-color-background`, `--ngx-color-surface`, `--ngx-color-surface-raised`         |
| Text                    | `--ngx-color-text`, `--ngx-color-text-muted`                                          |
| Borders and focus       | `--ngx-color-border`, `--ngx-color-focus-ring`                                        |

These variables provide shared color values for component states, surfaces, text, and accessibility-related focus styling.

### 4.2 Spacing

The spacing scale uses `rem` values:

```css
--ngx-space-1: 0.25rem;
--ngx-space-2: 0.5rem;
--ngx-space-3: 0.75rem;
--ngx-space-4: 1rem;
--ngx-space-5: 1.25rem;
--ngx-space-6: 1.5rem;
--ngx-space-8: 2rem;
--ngx-space-10: 2.5rem;
--ngx-space-12: 3rem;
--ngx-space-16: 4rem;
```

Use these tokens for component padding, margins, gaps, and layout spacing.

### 4.3 Typography

The typography tokens include:

- Base font family.
- Font sizes from extra-small to 3XL.
- Normal, medium, semibold, and bold font weights.
- Tight, normal, and relaxed line heights.

Example:

```css
.heading {
  font-size: var(--ngx-font-size-xl);
  font-weight: var(--ngx-font-weight-semibold);
  line-height: var(--ngx-line-height-tight);
}
```

### 4.4 Borders and elevation

The foundation defines:

- Small, medium, large, and full border radii.
- A standard border width.
- Small, medium, and large box shadows.

Example:

```css
.card {
  border: var(--ngx-border-width) solid var(--ngx-color-border);
  border-radius: var(--ngx-radius-lg);
  box-shadow: var(--ngx-shadow-sm);
}
```

### 4.5 Layering

The z-index tokens establish named layers for dropdowns, sticky content, overlays, modals, and tooltips.

```css
--ngx-z-dropdown: 1000;
--ngx-z-sticky: 1100;
--ngx-z-overlay: 1200;
--ngx-z-modal: 1300;
--ngx-z-tooltip: 1400;
```

These values establish an initial convention. Future overlay and component implementations should validate their stacking requirements against the framework's layering rules.

## 5. Stylesheet Responsibilities

### `tokens.css`

Defines the light-theme defaults on `:root`, including color, spacing, typography, border, shadow, and z-index variables.

### `themes/dark.css`

Overrides the applicable custom properties when the following attribute is present:

```html
data-ngx-theme="dark"
```

The stylesheet also sets `color-scheme: dark`.

### `base.css`

Provides baseline styles:

- `box-sizing: border-box`.
- Base font family and line height.
- Visible keyboard focus outlines.
- Inherited font settings for form controls.
- Reduced-motion adjustments for animations and transitions.

These rules use `:where()` to keep selector specificity low.

### `index.css`

Acts as the stylesheet entry point and imports the base styles and light-theme tokens.

The dark theme is maintained as a separate stylesheet, which must be included in the consuming build for dark-mode overrides to be available.

## 6. Theme Behavior

### Light theme

The light theme is the default because its variables are defined on `:root`.

### Dark theme

The dark stylesheet applies overrides when an element matches:

```css
[data-ngx-theme="dark"] {
  color-scheme: dark;
  /* Dark-theme custom-property overrides */
}
```

For the current Host smoke test, the theme state is toggled from Angular and the `data-ngx-theme="dark"` attribute is applied to the document root.

CSS custom properties inherit from the element on which they are defined to its descendants. This allows the Host content to consume the dark values when the root element has the attribute.

The browser smoke test confirmed that the page background, card surface, text, borders, and primary button respond to the dark-theme tokens.

## 7. Host Integration

The Host application currently imports the source stylesheet entry point from `apps/host/src/styles.scss`.

The current integration uses a relative source import:

```scss
@import "../../../libs/design-tokens/src/lib/styles/index.css";
```

This is a local development integration. It demonstrates that the styles can be included in the Host application build.

Component styles consume the tokens using standard CSS custom properties:

```scss
.token-card {
  padding: var(--ngx-space-6);
  color: var(--ngx-color-text);
  background: var(--ngx-color-surface);
  border: var(--ngx-border-width) solid var(--ngx-color-border);
  border-radius: var(--ngx-radius-lg);
}
```

A test button also uses the primary and hover tokens:

```scss
.demo-button {
  color: white;
  background: var(--ngx-color-primary);
}

.demo-button:hover {
  background: var(--ngx-color-primary-hover);
}
```

The explicit `white` foreground is currently part of the smoke-test example. Future component implementations should verify foreground/background contrast across both themes and use appropriate semantic tokens where necessary.

## 8. Accessibility and Baseline Behavior

The base stylesheet provides a visible `:focus-visible` outline and includes a reduced-motion media query.

These are initial global defaults, not a complete accessibility implementation. Individual components must still provide appropriate semantic HTML, keyboard behavior, accessible names, and contrast.

Future accessibility validation should include keyboard navigation, focus visibility, automated accessibility checks, and manual review.

## 10. Current Limitations and Follow-up Work

The following items remain outside the completed smoke-test scope:

1. **Public package CSS exports:** Verify a supported Angular package configuration for exposing stylesheet entry points to external consumers.
2. **Consumer installation test:** Validate stylesheet imports from the built package rather than relying only on the Host's relative source import.
3. **Token documentation:** Add a complete token reference or generated token table as the token set grows.
4. **Theme API:** Define a consistent theme activation API for applications and component consumers.
5. **Contrast validation:** Check text and interactive-state contrast in light and dark themes.
6. **Design-token tests:** Consider automated checks for token availability, theme overrides, and generated package contents.
7. **Unused schematic component:** Review whether the generated `DesignTokens` Angular component and its test should be removed if they are not part of the intended public API.
